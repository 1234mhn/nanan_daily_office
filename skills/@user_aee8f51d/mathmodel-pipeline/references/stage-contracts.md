# 阶段产出契约

各阶段报告的最小结构。按题目实际问题数 N 动态组织，示例中的 Q1..Qn 表示"每一问都要有对应小节"，不是固定三问。

## 1. reports/ANALYSIS_MODELING_REPORT.md（步骤 1 产出）

```markdown
# 建模报告

## 1. 总体建模框架
## 2. 数据处理方案          # 每份附件：行列规模、字段含义、缺失/异常/重复、单位
## 3. 符号说明
## 4. 问题分析（Q1..Qn，每问一节）
    每问必须包含：题目要求、输入输出、决策变量或预测对象、
    目标函数或评价指标、约束条件、与其他问题的依赖关系、
    求解方法（含停止条件与复杂度）、计划生成的图表
## 5. 假设敏感性预检
    对影响结果的歧义：至少两种解释 → 快速验算 → 最终采用哪种及理由
## 6. 灵敏度分析与检验方案
## 7. 代码实现任务清单
| 任务 | 输入 | 输出 | 方法 | 校验 |
| --- | --- | --- | --- | --- |
| Q1  | ...  | ...  | ...  | ...  |
## 8. EVIDENCE_GAP 登记
    EVIDENCE_GAP: <缺什么> <影响哪一问> <建议补齐方式>（无则写"无"）
```

## 2. reports/RESULTS_REPORT.md（步骤 3 产出，随跑随写）

```markdown
# 计算结果

## 运行环境                    # Python 版本、关键包版本、随机种子
## 数据读取与预处理            # 清洗规则和清洗后的规模，产物存 results/
## Q1 结果
    方法与参数 → 关键数值（保留与误差匹配的位数）→ 产物文件清单 → 校验结论
## Q2 结果 ...（按实际 N）
## 灵敏度分析
## 约束与一致性校验
## 与建模报告的一致性说明      # 模型若有调整，写明调整点
## 可复现运行方式
## EVIDENCE_GAP 登记           # 本阶段新增缺口；上一阶段的缺口补齐情况
```

所有 `results/` 文件必须在本报告中有一行用途说明。优化类先保证可行解再优化目标值；预测类必须做训练/验证划分或误差评估；评价类必须说明指标方向、归一化方法和权重来源。

## 3. reports/PAPER_CONTENT_PLAN.md（步骤 5 产出）

```markdown
| 问题 | 题目要求 | 输入/输出 | 模型与参数 | 核心论点 | 结果证据 | 验证/边界 | 正文章节 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Q1  | ...     | ...      | ...       | ...     | results/q1_metrics.csv | 分组交叉验证 | 5_problem1 | READY |
```

- "结果证据"一格必须绑定 `results/` 或 `figures/` 的真实文件，没有真实证据的格子标 `EVIDENCE_GAP`，不得填空话。
- 状态取值：`READY` / `GAP`（有未核销 EVIDENCE_GAP）/ `BLOCKED`。
- 摘要、问题重述、正文入口和结果章节引用的问题集合必须与本题面清单完全一致。

## 4. 论文章节结构（步骤 7，按实际 N 动态增减问题章节）

```text
paper/
├── main.tex（或 main.typ / paper.md）
├── sections/
│   ├── 1_restatement   问题重述：背景、任务分解、研究目标三层
│   ├── 2_analysis      问题分析：每问一个分析小节
│   ├── 3_assumptions   模型假设（每条假设附合理性说明）
│   ├── 4_symbols       符号说明
│   ├── 5_problem1      Q1：模型建立 → 算法与参数 → 结果与验证 → 小结
│   ├── 6_problem2      Q2 ...（按 N）
│   ├── 8_evaluation    灵敏度、模型评价与推广
│   ├── A_code          附录：本次运行所用完整源代码
│   └── references      参考文献文件
```

每个问题章节的最低内容：模型公式或目标函数、算法与参数来源、至少一张真实结果表或图并配解释段落、与模型类型匹配的验证证据、适用边界与明确小结。

### 摘要契约（最后写）

- 中文摘要（含标题与关键词）原则上不超过一页；MCM/ICM 用英文 Summary Sheet。
- 必须覆盖**每一问**的方法与**精确**数值结果，数值与 RESULTS_REPORT 完全一致（同一位数口径）。
- 不出现"效果很好""误差较小"这类无数值表述；不出现内部文件名和内部流程词。

### 按模型类型选择验证证据

| 模型类型 | 至少报告 |
| --- | --- |
| 连续回归 / 响应面 | 分组交叉验证或 Bootstrap，另加残差、误差区间、基线比较或系数稳定性之一 |
| 分类 | 按合理单位划分训练验证集；混淆矩阵与不平衡指标；概率模型加校准或 Brier |
| 优化 / 决策 | 约束可行性、基线或替代方案比较、参数扰动下稳定性 |
| 评价 / 综合评价 | 指标方向与量纲处理、权重来源、排序对扰动的稳定性 |
| 预测（时间序列等） | 滚动起点验证或留出集误差、区间覆盖率 |

同一篇论文混合多种模型时按问题分别验收，不得用一个通用指标替代。

## 5. reports/VERIFY_REPORT.md（步骤 9 产出）

结构见 `verification-checklist.md`。必须包含：结论（PASS/FAIL）、检查项表、返工轮次记录、EVIDENCE_GAP 核销情况、无人值守门禁中"默认采用（未经用户确认）"的决策清单。

## 6. 拟合与数值实验防错清单（源自真实竞赛实测）

1. **参数可辨识性先行**：非线性拟合前确认每个参数独立影响目标函数；若拟合结果贴到边界（上下界），几乎必然是参数简并或设定错误——实测案例：条纹频率只约束乘积 n₁·d，单独拟合 n₁ 会滑向边界。修法：固定物理常数（作为已声明假设），或改参数化为可辨识组合。
2. **链式中间结果先可视化再信任**：极值序列、游程、配对类算法（干涉条纹极值检测等）必须先画出中间序列与间距分布，检查假峰（间距远小于中位步长）、漏检（约 2 倍步长的跳步）、序错定（回归残差成片偏移）；用 2.5σ 迭代剔野 + 整数序（丢峰容忍）回归兜底。
3. **方法互验**：每个关键数值至少用 3 种互不相依的方法得出（如极值回归 / 正弦全谱 / 带谐波全谱 / 精确模型拟合），互差入结果表。
4. **鲁棒性扰动**：对算法超参（平滑窗口、网格密度、阈值）做 ±50% 级扰动，报告结果极差；极差进不确定度讨论。
5. **未知物理常数**：取文献典型值 + 敏感性区间（如 ±0.03），作为假设声明并计入不确定度；不编造色散公式，缺数据按 EVIDENCE_GAP 登记为局限。
6. **粗差识别即弃用**：某方法在某子窗口给出与其他方法差数倍的值（实测案例：低衬比段极值链断裂给出 4.695 vs 3.44），识别后弃用该方法在该窗口的结果，改用可靠窗口或全谱拟合，并在论文中如实声明失效模式。
