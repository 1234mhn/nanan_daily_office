# 质询门禁协议（门禁 A / B / C 共用）

三个门禁位置：

- **门禁 A · 方案质询**（步骤 2）：`ANALYSIS_MODELING_REPORT.md` 初稿完成后、生成最终"代码实现任务清单"前。聚焦题意解释、数据口径、假设、变量、目标函数、约束、求解与验证方案。
- **门禁 B · 论证计划质询**（步骤 6）：`PAPER_CONTENT_PLAN.md` 完成后、正式撰写正文前。聚焦论点是否有证据绑定、章节映射、结论强度。
- **门禁 C · 成稿质询**（步骤 8）：实际问题章节完成后、撰写最终摘要和交付前。聚焦数值一致性、验证覆盖、图表叙事、引用支持、适用边界。

## 提问前核对（每个门禁第一轮之前）

1. 核对题面实际顶层问题数量及问题间依赖，不从模板推断。
2. 核对附件字段、单位、缺失值、异常值、时间范围、样本粒度（门禁 A）；核对每个论点的证据文件是否真实存在（门禁 B/C）。
3. 能从题面、数据、已有报告或简单验算确定的问题**自行作答并写回报告**，不占用用户问题名额。
4. 只把会改变模型结构、实现口径、论点证据或结论强度的高影响未知项交给用户。

没有高影响未知项时，不凑数提问，记录"无需用户决策"，通过一致性核对后直接放行。

## 批量质询规则

- 每个门禁最多 3 轮，高影响不确定性提前消除时提前结束。
- 每轮最多 10 个编号问题；第一轮原则上 10 个，实际不足时只问存在的问题。
- 后续轮次只追问未解决的高影响项，不重复已确认内容。
- 一次发出整批问题，等整批回复后再继续。
- 每问必须给推荐答案和理由，方便用户"全部采用推荐答案"。

```markdown
<门禁名称> · Round 1 of 3

1. <具体问题>
   影响：<模型 / 数据 / 实现 / 论点 / 结论强度>
   推荐答案：<推荐选择及理由>
```

用户回复与题面、数据或现有结果冲突时，必须先指出冲突再收口，不能直接采用。

## 每轮回复后的处理

1. 汇总已确认的决定；与题面、数据和现有公式交叉核对。
2. 指出互相冲突、无法计算或会使后续条件失去边际效果的决定。
3. 把已确认内容写回对应报告（ANALYSIS_MODELING_REPORT / PAPER_CONTENT_PLAN / 论文草稿），不能只留在聊天记录里。
4. 更新门禁对应的质询报告（MODEL_GRILL_REPORT.md / PAPER_GRILL_REPORT.md），记录轮次、决定和剩余风险。
5. 判断是否还有高影响未知项，决定是否进入下一轮。

## 停止条件与门禁状态

满足任一条件停止提问：高影响未知项已解决；剩余问题只影响局部细节；已完成第三轮。

第三轮后仍未解决的问题作为显式风险和备选方案保留，不得伪装成已确定。

| 状态 | 含义 | 后续 |
| --- | --- | --- |
| `READY` | 无高影响未知项 | 继续下一阶段 |
| `READY_WITH_RISKS` | 有已记录风险或默认决定 | 继续下一阶段，风险带入 VERIFY_REPORT |
| `BLOCKED` | 存在补不齐且无法降级的证据缺口 | 暂停该分支，向用户列明缺口与补救路径 |

## 无人值守降级（本技能与原三角色流程的关键差异）

以下情况视为"用户离席"：用户明确说自动跑完/限时完成；或一个门禁批次发出后没有获得回复且环境不允许继续等待。

降级流程：

1. 该批次全部问题**采用各自推荐答案**继续推进。
2. 每项在质询报告中标注：`默认采用（未经用户确认）：问题 → 采用的推荐答案 → 主要风险`。
3. 门禁状态记 `READY_WITH_RISKS`（而不是 BLOCKED），流程继续。
4. 涉及"结论强度"的默认选择必须是保守方向：证据不足时降结论、写局限，不加强结论。
5. 所有默认决定汇总进 VERIFY_REPORT 的"默认采用决策清单"，供用户赛后复核。

禁止：因等待回复挂起；把默认决定写成用户已确认；用默认决定掩盖 EVIDENCE_GAP。

## EVIDENCE_GAP 的门禁处理

门禁中遇到 EVIDENCE_GAP 只有三种合法处理：

1. 退回产生方补真实证据（改报告或重跑受影响问题）；
2. 删除无证据论点；
3. 明确写入局限并降低结论强度。

不得用示例数值、模型记忆、未经核验文献或"结果表明"补洞。
