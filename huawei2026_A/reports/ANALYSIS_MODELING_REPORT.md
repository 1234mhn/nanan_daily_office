## 1. 总体建模框架

### 1.1 问题本质

本题是一个**多核异构流水线环境下的图划分 + 任务调度联合优化问题**，属 NP-难组合优化范畴。

三层耦合决策：

1. **切图（partition）**：把计算图中每个核内计算操作（非 COPY_IN/COPY_OUT）指派给一个子图 sgid；
2. **分核（assignment）**：把每个子图指派给一个 NPU 核心；
3. **排序（sequencing）**：确定每个核心上子图的执行顺序。

三层决策相互耦合：切图改变子图规模、并行空间与通信边界；分核决定负载均衡与跨核通信量；同核排序影响依赖等待、张量驻留时长与缓存换入换出。因此**不能孤立优化任一环节**，本报告采用"**切图—分核—排序联合建模 + 分层启发式求解**"的统一框架。

### 1.2 建模主线

```
原始计算图 G=(T,O,E)
   │
   ├─ ① 切图模型：决策 x_{o,s} ∈ {0,1}（操作 o 是否属于子图 s）
   │      约束：子图依赖图必须是 DAG；每个非 COPY 操作恰好属于一个子图
   │
   ├─ ② 分核模型：决策 y_{s,k} ∈ {0,1}（子图 s 是否分给核 k）
   │      约束：子图数不限，但需负载均衡
   │
   ├─ ③ 排序模型：决策各核上 sgid 的线性排列 π_k
   │      约束：π_k 不得违反子图间依赖（拓扑合法）
   │
   └─ ④ 评价模型：由赛题评估器模拟 → Makespan（主）、额外搬运量（次）、Cache 命中率
```

**关键认识**：目标函数（Makespan）**没有闭式表达式**，只能通过赛题评估器仿真获得。因此这是一个**黑箱目标函数下的组合优化问题**——这一点决定了求解必须采用"启发式生成候选 + 评估器打分 + 迭代改进"的范式，而不能用梯度或解析方法。

### 1.3 三问的关系

| | 场景 | Task 组织 | 子图间数据 | 新增硬件 |
|---|---|---|---|---|
| Q1 | A：无核间同步 | 1 子图 = 1 Task | 全部经 DDR 中转 | — |
| Q2 | B：有核间同步 | 同核全部子图 = 1 Task | 同核复用 L1/UB，跨核经 DDR | — |
| Q3 | B + L2 | 同 Q2 | 同 Q2 | 共享只读 L2（1MB / 250 B/cyc） |

**Q1 是地基**：Q2 在 Q1 的切图/分核/排序框架上替换通信成本模型并增加 L1/UB 容量硬约束；Q3 在 Q2 上叠加只读 Cache 资源与命中率优化目标。三问共用同一输出格式（`node_to_subgraph` + `core_schedules`）与同一套评估器。

## 3. 符号说明

### 3.1 集合与图

| 符号 | 含义 |
|---|---|
| $G=(T,O,E)$ | 计算图；$T$ 张量节点集，$O$ 操作节点集，$E$ 有向边集 |
| $O^{c} \subseteq O$ | 核内计算操作集合（非 COPY_IN/COPY_OUT），即**需要切图决策**的操作 |
| $O^{cp} \subseteq O$ | 搬运操作集合（COPY_IN / COPY_OUT），由评估器自动重建 |
| $S=\{0,1,\dots,m-1\}$ | 子图集合（sgid 集合），$m$ 为子图数（**不限**） |
| $K=\{0,1,\dots,N-1\}$ | 核心集合，$N \in \{1,2,3,4,5\}$ |
| $\mathcal{T} = \{t_1,\dots,t_p\}$ | Task 集合（子图→Task 的组织规则由场景决定） |

### 3.2 参数

| 符号 | 含义 | 取值 |
|---|---|---|
| $s(t)$ | 张量 $t$ 的字节大小 | 图给定 |
| $pos(t)$ | 张量 $t$ 的逻辑位置 | DDR / L1 / UB |
| $c(o)$ | 操作 $o$ 的核内计算周期数 | 图给定 |
| $B$ | DDR 总带宽 | 60 bytes/cycle |
| $C_{L1}, C_{UB}$ | L1 / UB 容量 | 524288 / 131072 bytes |
| $C_{L2}, B_{L2}$ | L2 容量 / 带宽 | 1048576 bytes / 250 bytes/cycle |
| $\lambda_{\text{cross}}$ | 跨核前驱等待 | 1000 cycles（Q1）/ 500 cycles（Q2,Q3 同步延迟） |
| $\lambda_{\text{switch}}$ | 同核 Task 切换等待 | 100 cycles（Q1） |

### 3.3 决策变量

| 符号 | 类型 | 含义 |
|---|---|---|
| $x_{o,s} \in \{0,1\}$ | 0-1 | 核内操作 $o \in O^c$ 是否属于子图 $s$ |
| $y_{s,k} \in \{0,1\}$ | 0-1 | 子图 $s$ 是否分配给核心 $k$ |
| $\pi_k$ | 序列 | 核心 $k$ 上子图的执行顺序（$k$ 的 sgid 排列） |
| $z_{s_1,s_2} \in \{0,1\}$（辅助） | 0-1 | 子图 $s_1$ 与 $s_2$ 间是否存在跨子图数据依赖 |
| $r_{s,k} \in \mathbb{Z}^+$ | 整数 | 子图 $s$ 在核心 $k$ 上 Task 内的执行次序（Q2/Q3 用） |

### 3.4 目标与指标

| 符号 | 含义 | 方向 |
|---|---|---|
| $\mathrm{MS}$ | Makespan，全部操作完成时刻的最大值 | 最小 |
| $\mathrm{DM}$ | 总额外数据搬运量（调度后 DDR 搬运 − 原始图搬运） | 最小 |
| $\mathrm{HR}$ | Cache 命中率（命中字节 / 总访问字节） | 最大 |
| $S_N$ | $N$ 核加速比 $= \mathrm{MS}_{1}^{\text{intra}} / \mathrm{MS}_{N}$ | 最大 |

## 4. 问题分析

### 4.1 问题 1：场景 A 下的多核切图与调度算法

#### 题目要求
场景 A 下，每个子图独立构成一个 Task，所有跨子图数据均须经 DDR 中转。建立多核切图与调度模型并设计求解算法，为每个非 COPY 操作分配 sgid，同时确定各核心上的子图执行顺序。主目标：最短 Makespan；兼顾额外搬运量。算法需在 2~5 核范围内稳定、高效生成高质量结果。

#### 输入 / 输出

- **输入**：计算图 $G$；核心数 $N \in \{1,\dots,5\}$；config.txt 固定参数。
- **输出**：`<case>_multicore_res.json`，含
  - `node_to_subgraph`：`{str(o): sgid}`，$o \in O^c$，恰好覆盖全部非 COPY 操作；
  - `core_schedules`：`[[sgid,...], ...]`，长度 = N，合并后每个 sgid 恰好出现一次，同核顺序不违反子图依赖。

#### 决策对象
切图 $x$、分核 $y$、排序 $\pi$（三个决策联合）。

#### 目标函数

$$\min_{x,y,\pi} \; \mathrm{MS}(x,y,\pi) \quad \text{s.t. 次要目标} \; \min \mathrm{DM}(x,y,\pi)$$

其中 $\mathrm{MS}(\cdot)$ 与 $\mathrm{DM}(\cdot)$ 由赛题评估器仿真给出，**无解析形式**。

#### 约束条件

| 类别 | 约束 |
|---|---|
| 覆盖性 | $\sum_{s \in S} x_{o,s} = 1, \; \forall o \in O^c$（每个非 COPY 操作恰好属于 1 个子图） |
| 无环性 | 由 $\{x\}$ 诱导的子图依赖图 $D(S)$ 必须为 DAG（至少存在一个拓扑序） |
| 分核覆盖 | $\sum_{k \in K} y_{s,k} = 1, \; \forall s \in S$；若 $S$ 中某子图为空则该 sgid 不应出现 |
| 排序合法性 | $\pi_k$ 是 $k$ 所辖子图的排列；任一子图在其所有前驱子图之后（同核时按 $\pi_k$ 序） |
| 执行语义 | Task 激活时刻 $\ge$ max(同核前一 Task 完成 + 100, 每个跨核前驱 Task 完成 + 1000) |
| 缓存容量 | 核内调度阶段自动处理（评估器负责，方案侧间接影响） |

#### 与其他问题的依赖关系

**Q1 是 Q2/Q3 的定义基础**：Q1 确定的切图框架、输出格式、加速比定义被 Q2/Q3 完全继承。Q1 无前置依赖。

#### 求解方法（模型 + 算法 + 停止条件 + 复杂度）

**建模层次**：
1. **通信代价模型（场景 A）**：任意两子图 $s_1,s_2$ 间若存在数据依赖边，则通信代价 $= \sum_{t \in \text{跨界张量}} s(t)$ 字节，全部经 DDR，单位成本统一；
2. **切图代价模型**：目标等价于在"减少跨界通信总量"与"保持子图规模均衡以支撑并行"之间权衡；
3. **负载模型**：核 $k$ 的负载 $\approx$ 其子图内计算周期之和 + 该核承担的搬运字节 $/B$。

**算法设计（分层启发式 + 评估器在环迭代）**：

```
算法 A1：场景 A 多核切图调度
─────────────────────────────────────────
阶段 1  初始切图
  1a. 计算操作依赖图（Op-Op DAG）：由 Tensor↔Op 二部图投影得到
  1b. 用"通信亲和度"加权的图划分（多层 KL/FM 或谱聚类）将 O^c 划为 m 个子图
      权重 = 边两端张量 size（跨界成本）；目标 = 最小化割边权重
  1c. 子图数 m 由粗到细扫描（m ∈ {N, 2N, 4N, ...}），选评估器打分最优者

阶段 2  分核
  2a. 子图依赖图 D(S) 上做列表调度（HEFT 式）：按"向上秩(upward rank)"排优先级
  2b. 每次把当前可调度的子图分给"预计最早完工"的核（考虑 1000/100 等待）

阶段 3  排序
  3a. 各核内部按子图依赖 + 完成时间邻域做局部调整（插入/交换）

阶段 4  迭代改进（评估器在环）
  4a. 邻域算子：① 移动单个操作到相邻子图；② 合并两个高通信子图；
      ③ 拆分过载子图；④ 交换同核两个子图顺序；⑤ 迁移子图到另一核
  4b. 用评估器打分，接受更好解（可加模拟退火/禁忌表避免局部最优）
  4c. 停止条件：达到时间预算 T_max 或连续 K 轮无改进（预声明 K=200，T_max 由评测限时决定）
─────────────────────────────────────────
```

**复杂度**：图划分阶段约 $O(|O^c| \log |O^c|)$（多层法）；列表调度 $O(|S| \cdot N)$；每次邻域评估需调用一次评估器（成本 $\approx O(|O| \cdot |S|)$ 级仿真）。整体在"评估器调用次数预算"内收敛。

**关键设计决策**：
- **子图数 m 是核心超参**——题目明说"子图数量不作限制"，因此 m 应作为搜索维度；
- 场景 A 下切细必然增加 DDR 搬运，所以 **m 不宜过大**，倾向"少切 + 充分负载均衡"。

#### 验证证据（优化/决策类）

- 约束可行性：所有输出方案必须通过评估器合法性检查（覆盖、无环、排序合法）——**必须 100% 通过**；
- 基线比较：与 `stub`（随机合法方案）比较，说明提升幅度；与"不切图（整图单核）"比较；
- 参数扰动稳定性：随机种子 × 若干次，报告 Makespan 极差；
- 与核数关系：2~5 核均需出结果。

### 4.2 问题 2：场景 B 下的多核切图与调度算法

#### 题目要求
场景 B 下，每个核心上的全部子图合并为一个 Task：同核子图可直接复用 L1/UB 中的数据，跨核依赖通过 COPY_OUT/COPY_IN 和固定同步延迟（500 cycles）完成。在**严格满足 L1/UB 容量约束**的前提下，进一步缩短 Makespan 并减少额外搬运。2~5 核稳定出解。

#### 输入 / 输出
同 Q1（输入加场景 B 语义；输出格式完全一致）。

#### 决策对象
同 Q1，但**分核的语义变了**：分核 = 分 Task；且**同核子图的排序 $\pi_k$ 直接决定数据驻留复用效果**。

#### 目标函数

$$\min_{x,y,\pi} \; \mathrm{MS}_B(x,y,\pi), \quad \min \mathrm{DM}_B(x,y,\pi)$$

#### 约束条件

| 类别 | 约束 |
|---|---|
| Q1 全部约束 | 覆盖性、无环性、排序合法性继续成立 |
| **L1/UB 容量硬约束** | 每个 Task 执行期间驻留张量之和 $\le C_{L1}/C_{UB}$（按 pos 分池）；**超限会被评估器自动换出换入**，因此这是"软执行、硬惩罚"约束——方案应主动避免超限 |
| 跨核同步 | 目标核的 COPY_IN 须在源核 COPY_OUT 完成 + 500 cycles 后才可进入就绪判定 |
| 同核复用 | 同核子图间不插边界 COPY，数据可留在 L1/UB |

#### 与其他问题的依赖关系
**依赖 Q1**：切图框架、算法骨架、输出格式。相对 Q1 **新增的关键约束**是容量硬约束与"合并负收益"现象。**Q3 依赖 Q2**。

#### 求解方法

**新增建模要素——"合并收益"模型**（本题的灵魂）：

设子图 $s_1, s_2$ 单独执行时间之和为 $T(s_1)+T(s_2)$，合并为同一 Task 后执行时间为 $T(s_1 \cup s_2)$，则

$$\Delta T = T(s_1) + T(s_2) - T(s_1 \cup s_2)$$

- $\Delta T > 0$：合并有正收益（省头尾搬运、省通信；流水掩盖开销）；
- $\Delta T < 0$：合并**负收益**（数据驻留挤爆缓存 → 换出换入开销 > 省下的搬运）。

题面明确指出负收益临界点的存在。因此**切图必须引入"缓存占用量"作为显式约束/惩罚**：

$$\text{Penalty}(s) = \alpha \cdot \max\!\left(0, \; \sum_{t \in \text{res}(s)} s(t) - C_{\text{pool}(t)}\right)$$

**算法设计**（在 A1 基础上改造）：

```
算法 A2：场景 B 多核切图调度
─────────────────────────────────────────
阶段 1  初始切图
  1a. 在 A1 的通信亲和度权重上，追加"缓存占用"权重：
      合并候选对 (s1,s2) 打分为 收益ΔT估计 − 缓存惩罚
  1b. 优先合并"共享同一输入数据"的操作（减少重复读取 —— 题面优化方向③）

阶段 2  分核 = 分 Task
  2a. 依赖 D(S) + 容量约束做列表调度
  2b. 同核内次序 π_k 由"数据驻留最大化"启发式定：
      让共享中间张量的子图在同一个 Task 内相邻执行

阶段 3  容量可行性修复
  3a. 对每个 Task 估驻留峰值；超容则拆分/调整顺序（优先保留大张量的生产者-消费者相邻）
  3b. 用评估器的 3 个 step（topo / evict / pipe）离线预演，避免容量爆掉

阶段 4  迭代改进（同 A1，增加"合并/拆分"邻域为主）
─────────────────────────────────────────
```

### 4.3 问题 3：共享 L2 资源下的多核切图与调度

#### 题目要求
在场景 B 基础上引入所有核心共享的只读 L2 Cache（容量 1MB，带宽 250 bytes/cycle，带宽独立于 DDR），研究其容量和带宽对多核切图与调度的影响，建立模型、设计算法。2~5 核稳定出解。

#### 输入 / 输出
同 Q2；但**实验配置变为两套**（无 L2 / 只读 Cache），输出需对比。

#### 决策对象
同 Q2（切图 / 分核 / 排序），但**切图策略要主动为 Cache 命中服务**。

#### 目标函数

$$\min \mathrm{MS}_{B+L2}(x,y,\pi), \quad \max \mathrm{HR}(x,y,\pi), \quad \min \mathrm{DM}$$

题目要求报告的对比量：**同核数下只读 Cache 相对无 L2 基线的加速比**

$$S_{\text{L2}}(N) = \frac{\mathrm{MS}_{N}^{\text{no-L2}}}{\mathrm{MS}_{N}^{\text{L2}}}$$

#### 约束条件
同 Q2，外加 L2 机制约束（由评估器实现）：按 **逻辑 tensor id** 查只读 FIFO Cache；命中走 L2 带宽池；未命中访问 DDR 后写入 Cache，满则 FIFO 淘汰；单张量 > L2 容量则不缓存。

#### 建模要点——Cache 命中模型

L2 复用"多核共享输入"。设张量 $t$ 被 $n_t$ 个不同子图（位于不同核）读取，若排布使它们的 COPY_IN 在时间上邻近，则第 1 次读入 L2 后，后 $n_t-1$ 次可命中：

$$\text{命中字节} \approx \sum_t s(t) \cdot (\text{实际命中次数}), \quad \mathrm{HR} = \frac{\text{命中字节}}{\text{总访问字节}}$$

**切图启示**：应把"读取同一共享输入 $t$ 的多个操作"安排在**时间上靠近的执行位置**（即使分属不同核/子图），以提高 L2 命中率。这是 Q3 相对 Q2 切图策略的核心区别。

#### 算法设计（在 A2 上追加）

```
算法 A3：场景 B + L2 多核切图调度
─────────────────────────────────────────
在 A2 基础上追加：
阶段 1'  共享输入识别
  统计每个 DDR 输入张量的"消费者集合"（读它的操作集）
阶段 2'  时间邻近性优化
  把共享同一输入的消费者在调度时间轴上拉近（同核相邻 / 跨核同时段）
  —— 这是提升命中率的主杠杆
阶段 4'  迭代目标改为加权：MS 为主，HR 为次
─────────────────────────────────────────
```
