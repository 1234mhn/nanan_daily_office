## 0. 一句话抓住题目

> 把一张 DAG 计算图，切成都市"子图"（决定通信边界）→ 分到 N 个同构 NPU 核上（决定并行度与均衡）→ 排定每个核上的子图顺序（决定缓存驻留与等待链）。
> **目标 Myspan 没有解析表达式**，只能由官方评估器仿真打分 → 本质是**黑箱目标下的图划分+调度联合组合优化**。
> 三问的差异**只在于"子图之间怎么传数据"这一条规则**，其余框架完全共用。

## 1. 第一块：问题 1（场景 A —— 无核间同步）

### 1.1 题目规则翻译成物理含义

| 题面规则 | 物理含义 | 对建模的硬影响 |
|---|---|---|
| 一个 Task 只能包含一个子图 | 核间**没有同步信号线**，CPU 主控是唯一的同步手段 | 子图粒度 = Task 粒度，调度是**两个层级**（核间 + 核内）而非三层 |
| 同一核上多个 Task 串行时**核内缓存状态被清空** | 每换一个 Task，L1/UB 相当于被 flush | **跨子图数据 100% 必须写回 DDR**，没有任何核内复用 |
| 任意两子图间单位通信成本相同（Cinner = Ccross） | 同核和跨核通信**一样贵** | 场景 A 下"把通信多的子图放同一个核"**不能省通信**，只能省等待 |
| 跨 Task 数据不驻留私有缓存 | 无 resident 数据 | 不需要"驻留容量"这个约束（对比 Q2 的核心约束） |

### 1.2 关键洞察（这块最容易做错的地方）

**洞察 1：场景 A 下"减少切分"和"增加并行"的矛盾是纯对抗的。**
因为 Cinner = Ccross，把两个强通信子图合并进同一个核**并不能**降低通信开销（数据照样要过 DDR）。合并的唯一收益是：
- 省掉一次 DDR 往返（合并后原本跨子图的边界张量变成了子图内部张量，**不再产生 COPY_OUT/COPY_IN**）；
- 省掉 Task 切换等待（同核 100 cycles / 跨核 1000 cycles）。

**所以场景 A 的核心矛盾是：切得越细 → 并行度↑ 但 DDR 往返次数↑；切得越粗 → DDR 往返↓ 但并行度↓ 且单核串行段变长。**
这解释了为什么题面说"场景 A 下应倾向少切 + 充分负载均衡"——但**不能切到只剩 N 块**，因为子图内部还需要用 Cube/Vector 并行和流水掩盖来吃掉搬运延迟。

**洞察 2：1000 vs 100 的等待差决定了"排序"在场景 A 下是有意义的决策。**
虽然通信成本相同，但**跨核前驱等待 1000 / 同核 Task 切换 100** 差了 10 倍。这意味着：
- 把一条依赖链上的子图**放在同一个核**可以省 900 cycles/次的等待；
- 所以 `core_schedules` 的排序**不是装饰**（题面附录 D.2 明说：Task 最早激活时刻 = max(同核前一 Task 完成+100, 每个跨核前驱完成+1000)）。

这是 Q1 里最容易被忽略的杠杆：**依赖链亲和性（chain affinity）**——把相邻两子图分到同一核，收益是 900 cycles 级别的。

**洞察 3：DDR 带宽是全局共享资源，60 bytes/cycle 读写共享。**
Makespan 最终由"多核并发搬运争用带宽"重算（附录 D.5，公平共享，按并发数结算）。因此：
- 单核算出来的"搬运工作量 / 60"之和 **≠** 实际耗时；
- 并发搬运会互相拖慢，**过度并行反而可能拉长 Makespan**（带宽墙）。

这就是为什么不能只优化"总搬运字节数"，还要优化**搬运的时间分布**——把搬运峰错开。

### 1.3 求解难点清单

| # | 难点 | 为什么难 | 应对方向 |
|---|---|---|---|
| D1 | 三层决策耦合 | 切图改变通信边界 → 改变分核收益 → 改变排序收益，闭环 | 分层启发式 + 评估器在环迭代（黑箱目标只能迭代） |
| D2 | 目标无解析式 | 不能求导、不能解析松弛 | 候选生成 + 打分 + 邻域搜索（SA/禁忌） |
| D3 | 子图数 m 自由 | 搜索空间多一维，且 m 对 Makespan 非单调 | 把 m 当超参做由粗到细扫描 |
| D4 | 带宽争用非线性 | 并发搬运互拖，字节数不能简单相加 | 结果必须实测，理论模型只做方向判断 |
| D5 | 规模未知 | 用例可能上万节点，评估器单次调用成本高 | 限制评估器调用预算；先用代理指标（割边量/负载方差）粗筛 |

### 1.4 可用杠杆（按性价比排序）

1. **依赖链并核**：把跨核前驱关系改造成同核顺序，每次省 900 cycles —— 高性价比，离散动作少。
2. **共享输入的消费者聚合**：同张量被多操作读 → 聚到同子图，避免多次 DDR 读（题面优化方向③）。
3. **装载均衡**：核间完工时刻拉平，避免"一核拖尾"决定 Makespan。
4. **搬运峰错开**：让各核的 COPY 不在同一时段爆发，缓解带宽争用。
5. **Cube/Vector 双管道负载均衡**：单子图内 PIPE_M 与 PIPE_V 工作量接近，避免一条管道空转（题面优化方向④）。

### 1.5 交付物与验收

- 正文：1~5 核平均加速比折线图（加速比 = 单核整图核内调度 Makespan / k 核多核 Makespan）。
- 附录：逐用例 Makespan + 总额外搬运量。
- 附件：可复现 Python 脚本。
- 验收硬线：**方案必须 100% 通过评估器合法性检查**（覆盖性 / 无环 / 排序合法），且 2~5 核均出结果。

## 2. 第二块：问题 2（场景 B —— 有核间同步）

### 2.1 规则变化与物理含义

| 规则 | 物理含义 | 建模影响 |
|---|---|---|
| 同核全部子图 = **1 个 Task** | 核内有同步，可以"攒一批"再统一执行 | Task 数量从 m 个变成 N 个 |
| 同核子图间**不插边界 COPY**，数据留 L1/UB | 核内数据复用成为可能 | **新增核心约束：驻留容量** |
| Cinner < Ccross | 核内通信便宜 | **鼓励把强通信子图放同核**（与 Q1 相反！） |
| 跨核：源核 COPY_OUT → 500 cycles 同步延迟 → 目标核 COPY_IN | 有同步信号但需 500 cycles 延迟 | 等待常数从 1000 变 500，且机制化 |

### 2.2 关键洞察

**洞察 1（本题的灵魂）：合并收益函数 ΔT 不是单调的。**
题面原话："一般情况下，两个子图合并后的子图执行时间，会小于两子图各自单独执行的时间之和……但当子图合并后的规模超过一定程度时，可能出现合并后负时间收益的现象。"

$$\Delta T(s_1,s_2) = T(s_1) + T(s_2) - T(s_1 \cup s_2)$$

- **正收益来源**：① 省掉子图间边界 COPY（头尾搬运开销被计算流水掩盖）；② 通信成本下降（Cinner < Ccross）；③ 核内数据复用。
- **负收益来源**：合并后单 Task 的驻留张量峰值超 L1/UB 容量 → 评估器（附录 C.2）自动**换出/换入** → 产生额外 DDR 搬运 + 额外延迟，且换出的开销可能大于省下的通信。

**因此 Q2 与 Q1 的本质区别是：Q2 必须显式建模"缓存占用"，并且这个约束不是线性的、不是可加的。**

**洞察 2：L1 与 UB 是分池的，不能混算。**
L1 = 524288 bytes（服务 PIPE_M/Cube），UB = 131072 bytes（服务 PIPE_V/Vector）。一个子图内如果既有 Cube 操作又有 Vector 操作，**两个池分别受约束**，不能把容量加在一起用。这意味着：
- 切图时要**分别估算 M 侧与 V 侧的驻留峰值**；
- 一个池爆了就会触发换出，哪怕另一个池还空着。

**洞察 3：同核子图顺序 π_k 在 Q2 下真正决定成败。**
因为同核内数据可驻留，**"谁先谁后"直接决定某个中间张量能否被下一个子图直接复用**。理想的顺序应当让"生产者子图 → 消费者子图"相邻，且驻留时间窗口尽量短（减少占用）。

**洞察 4：Task 合并是把双刃剑 —— 并行度下降。**
N 个核 → 只有 N 个 Task。如果某核的 Task 特别大，它就决定了 Makespan（长尾效应）。所以 Q2 的负载均衡比 Q1 更敏感。

### 2.3 求解难点清单

| # | 难点 | 说明 | 应对 |
|---|---|---|---|
| E1 | 合并收益非单调 | ΔT 有正有负，临界点未知 | 把"合并/拆分"作为核心邻域算子，用评估器实测 ΔT |
| E2 | 容量约束是"软失败" | 超容不报错，而是自动换出换入 → 静默劣化 | 方案侧必须**主动估峰值、主动避免超容** |
| E3 | L1/UB 分池 | 两池独立约束 | 分别建模，取两者中更紧的作为瓶颈 |
| E4 | 驻留窗口管理 | 数据留得越久越省通信，但越占容量 | 顺序优化：缩短中间张量存活窗口 |
| E5 | 评估器三阶段依赖 | topo → evict → pipe，顺序固定（附录 C） | 离线复现三阶段做预演，避免盲目搜索 |

### 2.4 可用杠杆

1. **共享输入聚合**（跨子图重复读取是额外搬运三大来源之一）。
2. **生产者-消费者相邻**：同核内把紧耦合子图排成一串。
3. **容量感知切图**：按 L1/UB 分池容量切，使单 Task 峰值不超容。
4. **避免超大 Task**：防止单核长尾 + 防止大子图触发大量换出换入（题面优化方向⑤）。
5. **跨核边最小化**：跨核要 500 cycles 同步 + 写 DDR 再读，比核内贵得多。

### 2.5 交付物与验收

- 正文：场景 B 下 1~5 核平均加速比折线图。
- 附录：逐用例 Makespan + 额外搬运量。
- 附录补充建议：**合并收益 ΔT vs 合并规模**曲线（直接呼应题面提示，是加分点）。
- 验收硬线：合法 + **容量可行**（不得出现评估器报 Task 失败）+ 2~5 核出解。

## 3. 第三块：问题 3（场景 B + 共享只读 L2 Cache）

### 3.1 规则变化

在 Q2 之上叠加：**所有核共享的只读 L2 Cache，1 MB 容量，250 bytes/cycle 带宽，带宽独立于 DDR。**
机制（附录 D.5）：
- COPY_IN 发射时按**逻辑 tensor id** 查只读 FIFO Cache；
- **命中** → 不改变 FIFO 顺序，走 L2 带宽池（250 B/cyc，独立不占 DDR）；
- **未命中** → 访问 DDR，完成后写入 Cache；容量不足按 **FIFO 淘汰**；
- 单个张量 > 1 MB → **不缓存**；
- Cache 带宽池与 DDR 带宽池**分别公平共享，互不占用**。

### 3.2 关键洞察

**洞察 1：L2 的收益完全来自"共享输入的时间邻近性"。**
L2 是**只读**且 **FIFO 淘汰**，不能主动保持热点。一个张量要能命中，必须满足：
> 它的**上一次读取**到**本次读取**之间，没有被足够的其它未命中张量把它 FIFO 挤出去。

⇒ 提升命中率的唯一手段：**让同一个共享输入张量的多个消费者在时间轴上靠近执行**（同核相邻 / 跨核同时段）。

**洞察 2：这是"带宽替换"而非"带宽叠加"。**
命中的 COPY_IN 从 DDR 池挪到 L2 池，**减少 DDR 争用**。所以 Q3 的收益有两层：
- 直接：命中的字节不再消耗 60 B/cyc 的 DDR 带宽；
- 间接：DDR 争用缓解 → 所有未命中搬运也变快 → Makespan 整体下降。

**洞察 3：1 MB 是硬门槛 —— 大张量直接出局。**
大于 1 MB 的张量根本不进 Cache。因此 Q3 的优化要**优先针对"中等大小 + 被多次读取"的张量**；大张量的重复读取只能靠"切图聚合"（把消费者并到一个子图/一个核）解决，不能靠 Cache。

**洞察 4：FIFO 淘汰意味着"访问顺序"比"访问次数"更重要。**
即使某张量被读 10 次，如果中间插入大量其他访问，它依然会被淘汰。所以切图/调度要**刻意压缩同一共享张量的访问间隔**。

**洞察 5：Q3 是"研究容量和带宽的影响"** —— 这意味着论文必须做**参数敏感性分析**（在 1MB/250B 附近扫描），不能只跑固定配置然后报个加速比。这是题目明确要求，也是与 Q2 的交付物差异。

### 3.3 求解难点清单

| # | 难点 | 说明 | 应对 |
|---|---|---|---|
| F1 | 命中率不可解析 | 依赖 FIFO 演化，只能仿真 | 用"访问间隔"做代理指标指导搜索 |
| F2 | 命中率与 Makespan 非一致 | 命中率↑不一定 Makespan↓（可能牺牲并行度） | 以 Makespan 为主目标，命中率为次 |
| F3 | 大张量不可缓存 | >1MB 直接出局 | 切图聚合消费者，绕开 Cache |
| F4 | 双带宽池结算复杂 | 两池独立公平共享 | 不能把 L2 收益简单折算成等效 DDR 带宽 |
| F5 | 无 L2 基线的口径 | 用 problem_2 还是 problem_3 关 Cache？ | 待实测确认；建议显式跑两套评估器对账 |

### 3.4 可用杠杆

1. **共享输入的消费者时间邻近**（主杠杆，直接提命中率）。
2. **访问间隔压缩**：调度时把同一张量的多次读取排密。
3. **中等张量优先**（1MB 以内、读取次数多）。
4. **大张量靠切图聚合**（不用指望 Cache）。
5. **平衡并行度与命中率**：过度聚合提命中但掉并行，需权衡。

### 3.5 交付物与验收

- 正文：1~5 核下"无 L2" vs "只读 Cache" **两条对比曲线**；同核数下只读 Cache 相对无 L2 的**加速比** $S_{L2}(N) = MS^{noL2}_N / MS^{L2}_N$。
- 附录：逐用例两种配置的 **Makespan + 额外搬运量 + Cache 命中率**。
- 建议补充：L2 容量/带宽敏感性曲线（呼应"研究其容量和带宽的影响"）。
- 验收硬线：合法 + 容量可行 + 两组对照齐全 + 2~5 核出解。

## 4. 第四块：算法优化方向（题面给的六条，逐条拆解）

> 这块不是独立问题，而是**贯穿三问的优化杠杆**。题面给了 6 条，逐条翻译成可操作的动作。

| # | 题面原话要点 | 物理机理 | 可操作动作 | 主要作用问题 |
|---|---|---|---|---|
| O1 | **子图间通信成本**：强通信依赖的两子图合并可降通信，但牺牲并行 | 边界张量不再产生 COPY | 以"跨子图边的张量 size 之和"作为合并评分的主项 | Q1/Q2/Q3 |
| O2 | **多核并行度**：过度聚合压缩并行，过度切分放大通信 | m 与并行度、通信的双向trade-off | m 作为超参扫描；负载方差作约束 | Q1/Q2/Q3 |
| O3 | **数据重复读取代价**：共享输入的消费者若被切开，各自从 DDR/L2 读 | 同一张量被读 n 次 = n 份带宽 | 统计每个 DDR 输入的消费者集合 → 强制聚同一子图/同核 | Q1/Q2/Q3（Q3 尤其） |
| O4 | **单核内 Cube/Vector 自动并行**：两单元可同时独立执行 | PIPE_M 与 PIPE_V 各自串行、彼此并行 | 切图时让同子图内 M 侧与 V 侧周期数接近 | Q1/Q2/Q3 |
| O5 | **核内启发式调度对大规模图的效率**：大子图触发换入换出，合并过多出现负收益 | 附录 C 是启发式，非全局最优 | 限制子图规模上限；用 ΔT 实测判断合并是否划算 | Q2/Q3（Q1 也有） |
| O6 | **单核内通信对缓存资源的占用**：驻留数据持续占缓存，压缩其他子图空间 | 附录 C.2 的驻留机制 | 排序时缩短中间张量的存活窗口 | Q2/Q3 |

**小结：O1/O2/O3 是"切图什么"的问题，O4/O5 是"切多细"的问题，O6 是"怎么排"的问题。**
⇒ 三问的算法都应该是"**切图（含 O1/O3 亲和度）→ 分核（O2 均衡）→ 排序（O6 驻留）→ 评估器在环迭代（O5 用实测 ΔT 收敛）**"这套骨架，只是各问题的通信成本模型与约束不同。

## 5. 三问对比总表

| 维度 | Q1 场景 A | Q2 场景 B | Q3 场景 B + L2 |
|---|---|---|---|
| Task 组织 | 1 子图 = 1 Task | 同核全部子图 = 1 Task | 同 Q2 |
| 同核数据复用 | ❌ 缓存被清空 | ✅ 留 L1/UB | ✅ 留 L1/UB |
| 通信成本 | Cinner = Ccross | Cinner < Ccross | 同 Q2 + 命中走 L2 |
| 等待常数 | 同核 100 / 跨核 1000 | 跨核同步延迟 500 | 500 |
| 核心约束 | 无缓存约束（不复用） | **L1/UB 分池容量硬约束** | 同 Q2 + L2 1MB FIFO |
| Task 数 | m（子图数） | N（核数） | N |
| 额外搬运主要来源 | 跨子图 DDR 往返 | 跨核 COPY + 容量换出换入 | 同 Q2（命中可抵消一部分） |
| 主目标 | Makespan | Makespan | Makespan |
| 次目标 | 额外搬运量 | 额外搬运量 + 容量可行 | 额外搬运量 + **Cache 命中率** |
| 论文点名的图 | 1~5 核加速比折线 | 1~5 核加速比折线 | 无 L2 vs 只读 Cache 对比曲线 + $S_{L2}(N)$ |
| 增量难度 | 基础 | 合并收益非单调 + 容量约束 | FIFO 命中率优化 + 容量/带宽敏感性 |

## 6. 题目埋的坑（逐条提醒）

1. **`node_to_subgraph` 必须"恰好"覆盖全部非 COPY 操作** —— 漏一个就整体无效；COPY_IN/COPY_OUT **不能**出现在映射表里（由评估器自动重建）。
2. **子图依赖图必须无环** —— 切图时若把一条依赖路径"反向"切了（例如操作 a 依赖 b，却把 a 分到更早的子图），依赖图会成环，方案直接废。
3. **每个 sgid 必须且只能出现在 core_schedules 中一次** —— 空子图/重复子图都会挂。
4. **config.txt 不得修改**（题面硬性要求）—— 灵敏度分析只能"仿真外部扫描"，不能改这个文件。
5. **单核加速比基准 = 整图不切的核内调度 Makespan**，不是"1 核多核评估"——两者不同，容易搞混。
6. **L1 与 UB 分池**，容量不能相加。
7. **>1MB 的张量不进 L2**，别在 Q3 里指望它。
8. **场景 A 里"同核"并不省通信**（Cinner = Ccross），只省等待（1000→100）。这是 Q1 与 Q2 策略相反的根源。
9. **搬运字节数不能简单相加等于时间**（带宽争用、公平共享重算）。
10. **评估器的核内调度是启发式**（附录 C 三阶段），所以"理论上更优的切法"未必实测更优 —— **必须实测**。
