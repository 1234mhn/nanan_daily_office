# A题深度分析（简洁版）

> 题面只有 3 问（Q1/Q2/Q3），第 4 块是贯穿三问的优化方向。
> 一句话：把计算图切块 → 分到 N 个 NPU 核 → 排每个核上的顺序；Makespan 没有公式，只能靠官方评估器打分，所以必须"生成候选 + 实测迭代"。

---

## Q1 场景A（无核间同步）

**规则**
- 1 个子图 = 1 个 Task。
- 换 Task 就清空核内缓存，所以跨子图数据全部走 DDR。
- 同核、跨核通信成本一样贵（Cinner = Ccross）。
- 同核前一个 Task 完成等 100 周期，跨核前驱完成等 1000 周期。

**核心洞察**
1. 场景A里"把强通信子图放同一个核"**不省通信**（还是过 DDR），只省等待。这跟 Q2 策略正好相反。
2. 真正的杠杆是**那 1000 和 100 的差距**：把依赖链上的子图放同核，每次省 900 周期。
3. 矛盾是纯对抗：切得越细，并行度越高，但 DDR 往返越多。

**怎么做**
- 子图数 m 由粗到细扫（m = N, 2N, 4N…），选实测最好的。
- 优先"依赖链并核"（省 900）。
- 把读同一张量的操作聚到同一个子图（少读几次 DDR）。
- 各核负载拉平，别让一核拖尾。

---

## Q2 场景B（有核间同步）

**规则**
- 同一个核上的所有子图合并成 1 个 Task，核内数据可以留在 L1/UB 复用。
- 跨核之间：源核写数据到 DDR → 等 500 周周期同步 → 目标核再读。
- 核内通信比跨核便宜（Cinner < Ccross）。
- L1 = 524288 字节，UB = 131072 字节，**两个池分开算，不能相加**。

**核心洞察**
1. **合并收益不是越多越好（本题灵魂）**：两个子图合并有好处（省边界搬运、省通信、能复用），但合并太大就会撑爆核内缓存，评估器自动换出换入，反而更慢。题面明说有这个"负收益临界点"。
2. **超容量不会报错，是静默变慢**。方案必须自己估峰值、自己避坑。
3. L1 和 UB 分开约束，哪个先爆哪个是瓶颈。
4. 同核内顺序**真正决定成败**：谁先谁后决定中间数据能不能被下一个子图直接复用。

**怎么做**
- 把"合并/拆分"当成主力搜索动作，用实测 ΔT 判断划不划算。
- 同核内让"生产者 → 消费者"相邻，缩短数据占用时间。
- 按 L1/UB 分池估峰值切图，别超容。
- 别做出特别大的 Task（会触发大量换出换入，也拖长 Makespan）。

## Q3 场景B + 共享只读 L2

**规则**
- 在 Q2 基础上加一个所有核共享的只读 L2：1 MB，250 字节/周期，带宽独立于 DDR。
- 命中 → 走 L2 带宽（不占 DDR）；未命中 → 读 DDR 并写入 L2，满了按先进先出淘汰。
- 单个张量大于 1 MB 就完全不缓存。

**核心洞察**
1. L2 的收益**只来自"共享输入被读的时间靠近"**。它是只读 + FIFO，不能自己保温。
2. 本质是**把 DDR 的活挪给 L2**，同时缓解 DDR 争用，两层收益。
3. **超过 1 MB 的张量别指望 L2**，只能靠切图把它的多个消费者聚到一起。
4. FIFO 意味着"读得密"比"读得多"更重要——中间插入别的访问就会被挤出去。

**怎么做**
- 主杠杆：把读同一个共享输入的操作在时间轴上拉近（同核相邻 / 跨核同时段）。
- 优先照顾"中等大小 + 被多次读"的张量。
- 大张量靠切图聚合，不靠 L2。
- 题目要求研究容量和带宽影响 → 必须做 1MB/250B 附近的参数扫描。

## 优化方向（第4块，贯穿三问）

**切什么**
- 强通信的两子图合并 → 省边界搬运，但掉并行度。
- 读同一份数据的操作聚到一起 → 少重复读 DDR。

**切多细**
- 子图数 m 是超参，过度聚合掉并行，过度切分涨通信。
- 子图太大还会触发核内换出换入（核内调度是启发式，不是最优）。

**怎么排**
- 缩短中间数据的存活时间，别让它一直占缓存。
- 单子图内让 Cube 和 Vector 的工作量接近，两个管道都别闲着。

## 十个坑

1. 映射表必须**恰好覆盖全部非 COPY 操作**，漏一个全废；COPY 操作不能写进去。
2. 子图依赖图必须无环，切反了直接废。
3. 每个 sgid 在 core_schedules 里必须出现且只出现一次。
4. **config.txt 不许改**。
5. 单核加速比基准 = 整图不切的核内调度 Makespan。
6. L1 和 UB 分池，容量不能相加。
7. 大于 1 MB 的张量不进 L2。
8. 场景A里同核**不省通信**，只省等待。
9. 搬运字节数不能直接换算成时间（带宽要争用重算）。
10. 评估器核内调度是启发式的，"理论更优"未必实测更优，**必须实测**。

## 三问对比

| | Q1 | Q2 | Q3 |
|---|---|---|---|
| Task 组织 | 1 子图 = 1 Task | 同核全部子图 = 1 Task | 同 Q2 |
| 核内复用 | 不行 | 可以 | 可以 |
| 通信成本 | 同核=跨核 | 核内更便宜 | 同 Q2 |
| 新增约束 | 无 | L1/UB 容量 | 容量 + L2 |
| 主难点 | 切分与并行对抗 | 合并收益非单调 | FIFO 命中率 |
| 论文要的图 | 1~5 核加速比 | 1~5 核加速比 | 无 L2 vs 只读 Cache 对比 + 加速比 |
