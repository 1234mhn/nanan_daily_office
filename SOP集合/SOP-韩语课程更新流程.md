### ② 直接从COS截取视频（🚫 不下载原片！）

| 步骤 | 操作 | 工具 |
|:---|:---|:---|
| 1 | 用COS脚本生成签名URL | `tencent-cos-skill` |
| 2 | ffmpeg从签名URL直接截取 + HDR→SDR转码 | `ffmpeg` |
| 3 | 上传截好的视频回COS | `tencent-cos-skill` |
| 4 | 拿到COS访问链接 | `tencent-cos-skill` |

```bash
# 生成签名URL（7200秒有效期）
node cos_node.mjs sign-url --key "原片路径" --expires 7200

# 🔴 HDR→SDR 标准转码（唯一正解，逐字照抄）
ffmpeg -v error -ss 起 -to 止 -i "签名URL" \
  -map 0:v:0 -map 0:a:0 \
  -vf "zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709:r=tv,tonemap=hable:desat=0,zscale=t=bt709:m=bt709:r=tv,scale=1920:1080,format=yuv420p" \
  -c:v libx264 -crf 20 -preset medium \
  -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
  -c:a aac -b:a 192k -ac 2 -movflags +faststart \
  "爱情怎么翻译 03-52.mp4" -y   # 文件名按命名规范

# 🔴 出厂校验闸（上传COS前必跑，不过关禁止上传）
bash /www/korean_course/_脚本工具/verify_sdr.sh "爱情怎么翻译 03-52.mp4"
# 必须退出码0 + 元数据 bt709/bt709/bt709，否则重转
```

**为什么这样才对（三个必须点，漏一个必坏）：**
1. **`zscale` 色域链**＝真正做 HDR→SDR 转换（`tonemap=hable:desat=0` 保饱和）；漏这条＝HDR原样透传＝偏暗偏绿
2. **`-colorspace/-color_primaries/-color_trc` 三个标签**＝给成品贴对元数据；像素转对但没写标签→浏览器仍按HDR显示。**最易漏的一步**
3. **`-ac 2`**＝原片5.1六声道，不降轨直接报错转不出

**🔴 HDR→SDR色调映射（必做，否则视频黢黑）**
**🔴 绝不在服务器上下载9GB原片——视频全程在COS上操作**

## 💰 流量省钱铁律（2026.9.12 订 · 治「几百块账单」）

> 🔴 **背景**：COS 外网下行约 0.5 元/GB，整集原片约 9GB。**每次从签名URL远程截取，ffmpeg 实际会读大量数据（往往接近整集）→ 一次截取≈4.5元**。做几十次加课就烧掉几百块。存储反而几乎不花钱（1.73GB≈2毛/月）。

**1. 一次拉原片，连截多段（最重要）**
- ❌ 禁止：一集里为每个课号单独 generate 一个签名URL 单独截一次
- ✅ 正确：同一集原片**只生成 1 个签名URL，一次 ffmpeg 命令用 `-ss/-to` 连续截多个片段**，或在一个 ffmpeg 进程里多输出

```bash
# ✅ 一次签名URL，一条命令截多段（同一集）
URL=$(node cos_node.mjs sign-url --key "原片路径" --expires 7200 | jq -r .url)
for spec in "l51:2339:2521" "l52:2530:2703" "l53:2813:2924"; do
  IFS=':' read -r name ss to <<< "$spec"
  ffmpeg -ss $ss -to $to -i "$URL" -map 0:v -map 0:a:0 \
    -vf "zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,format=yuv420p,scale=1920:1080" \
    -c:v libx264 -crf 22 -preset fast -c:a aac -b:a 192k \
    /tmp/ep5_lesson$name.mp4 -y
done
```

**2. 同集多次操作合并到同一次开工**
- 用户一次给同一集的多个课号 → 一次做完，别分几天反复拉

**3. 截取用 `-ss` 放在 `-i` 之前**
- 前置 `-ss` 可让 ffmpeg 快速 seek，减少实际读取的数据量（比放在 `-i` 后省流量）

**4. 字幕提取也别远程重复拉**
- 优先本地 MKV + mkvextract（见步骤③），避免为提字幕再拉一次原片
- 若必须远程，**复用同一个签名URL**，不要重新生成、不要重复拉

**5. 已切好的片段不要反复下载回本地校验**
- 校验用 `head` 看 size/etag 即可，不需要 download 整个文件

**6. 加课收尾记一笔流量**
- 汇报时写清：本次操作了哪几集原片、生成了几个签名URL、截了几段 → 便于复盘找出浪费点

| 14 | 台词时间戳用了整集时间轴，没按截取起点归零（第42课） | 🔴 截取后必须把台词时间戳减去视频截取起点秒数归零；校验范围0~视频时长，首句≈0、末句不超界。否则视频前半段无高亮、末尾字幕跟不上 |
| 15 | HDR→SDR转码参数错，成品画面偏青绿、偏暗、人物肤色发灰（第51课） | 🔴 转码必须显式带正确色域链：`zscale=t=linear:npl=100,format=gbrpf32le,zscale=p=bt709,zscale=t=bt709:m=bt709:r=tv,format=yuv420p`；成品色彩元数据必须 **bt709/bt709/bt709**（若为 bt2020nc/linear 即 HDR 没转对）。**转完抽查**：亮度过暗(avg<100)+绿色通道明显高于红(偏绿)即错，会返工。详见课程产品师SKILL Step1 |
