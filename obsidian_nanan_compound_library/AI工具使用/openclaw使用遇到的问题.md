# 🛠️ OpenClaw 使用遇到的问题

## 📝 使用感受

### 1. 记忆问题很大（最关注）
- 布置的任务有时会被忘掉。比如：我让他"在某个时间点提醒我做某件事"，他有的时候会把这个任务忘了，导致提醒没到。

### 2. 上下文读取缺乏局部性
- 感觉他在读取上下文时，会把之前所有的工作日志都翻一遍，没有做"局部读取"——只读当下需要的那部分，导致效率低、还可能抓不住重点。

### 3. 模型理解能力时好时坏
- 有时用这个模型不太"好使"，感觉它没太理解我的意思（可能也跟我自己表达不够清楚有关）。

### 4. 调用模型慢、还费 token
- 不知道为什么，调用中转站上的模型做东西时，有时候很慢，而且总会消耗我的 token。

### 5. token 用量偏大，缺少省 token 配置
- token 消耗比较大。我没有给 OpenClaw 配置一些"省 token"相关的 skill / 设置。

### 6. 支持多 sub-agent（子代理）并行运行
- 确认 OpenClaw 支持多个 sub-agent 并行干活（sessions_spawn 派生多个隔离子代理）。
- 这个能力如果利用好，可以并行处理多个任务，或把大任务拆给子代理，减少主会话上下文堆积。

## 🔧 遇到的问题 & 我的解决办法

- **问题**：布置的定时提醒任务有时会被忘掉，提醒没执行。
- **我的解决**：（待补充——可考虑改用系统 cron 定时任务，或明确要求写入待办并确认。）

### 2. 上下文读取范围过大
- **问题**：读上下文时似乎会把所有工作日志都读一遍，缺少局部读取。
- **我的解决**：（待补充——可约定：大任务先开新会话、只读需要的 memory/日志。）

### 3. 模型理解偏差
- **问题**：有时模型没理解我的意思（可能与我表达不清也有关）。
- **我的解决**：（待补充——可尝试把需求一次说清、用清单式表达。）

### 4. 调用慢 + 费 token
- **问题**：调中转站模型慢，且耗 token。
- **我的解决**：（待补充——可考虑改用更轻量的模型/优化调用频率。）

### 5. 缺少省 token 配置
- **问题**：token 用量大，没配省 token 的 skill。
- **我的解决**：（待补充——可让楠楠帮我配置省 token 的 skill/设置。）

- **我的解决**：（待补充——大任务可拆给子代理并行跑；批量化读取/搜索用子代理，减少主会话上下文堆积、省 token。）
