## 🔴🔴 严重事故记录（2026-11-14 14:12）—— git pull --rebase 导致本地文件被删
**经过：** 用户要求移除论文/研究类内容（只从 GitHub 移除、本地保留）。我用 `git rm --cached` 取消跟踪 → commit → `git pull --rebase` → **rebase 重放提交时，把本地文件一起删掉了**（17 个文件，含 2 个论文 PDF、10 个 md、research/、projects/）。
**原因：** `git rm --cached` 的删除操作在 rebase 重放时会重新执行一次，而此时文件已不在索引里，rebase 的 checkout 阶段把工作区文件一并清掉。
**恢复：** `git checkout 5e944a3 -- <文件列表>` 从历史 commit 完整恢复，17/17 全部找回，零丢失。
**🔴 以后铁律：**
1. **`git rm --cached` 后，绝不要在还有未提交状态时跑 `git pull --rebase`**
2. 移除跟踪的正确顺序：先 `git rm --cached` → **把文件复制到 .git 之外的备份目录** → commit → push（**不要** pull --rebase，或先 pull 再 rm）
3. **涉及删除/取消跟踪的操作，动手前必须先物理备份到 /root/backup_git_日期/ 目录**
4. 删完立刻 `ls` 逐项验证本地文件仍在，不能只看 git status
