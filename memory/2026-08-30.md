## 🔓🔑 飞书授权中断的终极解法（2026.8.30 12:37 用户要求记住，下次直接用）
**场景**：飞书 bitable 工具 create/batch_create 报 NOTEXIST / token过期，工具缓存的旧 token 失效。

**根因**：插件 bitable 工具读的是 `openclaw-feishu-uat` 加密 store（`/root/.local/share/openclaw-feishu-uat/cli_aa..._ou_499d...enc`），不是 `/tmp/feishu_token_store.json`。工具内存缓存了过期 token → 一切 create 失败。

**✅ 验证过的解法（直接用飞书 API 手动补录，绕开插件 store）：**
1. 发起设备授权（必须带 **Basic 认证** `appId:appSecret`，之前报 invalid_client 就是漏了这个）：
   - 端点：`https://accounts.feishu.cn/oauth/v1/device_authorization`（POST，form：client_id + scope）
   - 成功返回 device_code + verification_uri + user_code
2. 把 verification_uri (带user_code) 生成二维码发用户扫（`python3 -c qrcode`），**有效期10分钟**
3. 轮询 token 换 access_token：
   - 端点：`https://open.feishu.cn/open-apis/authen/v2/oauth/token`
   - grant_type=`urn:ietf:params:oauth:grant-type:device_code`（Basic 认证 + device_code）
   - authorization_pending 就 sleep几秒继续；拿到 access_token 写入 `/tmp/feishu_token_store.json`
4. **用该 access_token 直接调飞书 API 补录，不再走插件工具**：
   - 单条 create：`POST /open-apis/bitable/v1/apps/{app}/tables/{table}/records`，body={`fields`:...}
   - 批量：`…/records/batch_create`，body={records:[{fields},...]}
   - header：`Authorization: Bearer <access_token>` + `Content-Type: application/json`
   - 测试成功：HTTP 200 code 0，`data.record.record_id`
5. **不再尝试**：改插件加密 store（混合 ESM/CJS 会炸）、openclaw.json appSecret、批次授权按钮。
