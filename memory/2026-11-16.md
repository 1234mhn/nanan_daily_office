## 定时任务排查：「知识回炉重造」手机收不到

**现象**：今晚 22:00 任务执行 status=ok、lastDeliveryStatus=delivered，但用户手机没收到。

**排查过程**：
1. `openclaw channels status` → 微信通道 running，但 `lastInboundAt` 是 8 小时前
2. 用 message 工具实测发一条 → 用户确认收到 → **通道正常，不是掉线**
3. `openclaw cron get b3346673-...` → 发现 `delivery.accountId = "40b0b2566d05-im-bot"`
4. 对比当前实际账号 `d77dbdb4d09a-im-bot` → **账号对不上，配错了**

**修复**：
```bash
openclaw cron edit b3346673-4bb8-42f5-ae1b-ed6e63825475 --account d77dbdb4d09a-im-bot
```
（注：参数是 `--account` 不是 `--account-id`）

**教训**：
- cron 显示 delivered ≠ 真送达，`delivered` 只代表网关认为发出去了
- 微信多账号环境下，cron 的 `delivery.accountId` 必须是**当前在用的**那个，否则消息发到死账号
- 排查顺序：先实测通道（message 发一条）→ 再看任务配置 → 别一上来就重启
