### CheXmix 核心内容（带读要点）
- 反对 LLaVA 式「CLIP 编码器 + 投影层 + LLM」两段拼装：**投影层会扭曲视觉细节**，医学影像中细微征象至关重要。
- 解法：借鉴 Chameleon 早期融合 → VQ-GAN 把胸片编码成 **1024 个离散 token**，与文本 token 拼进同一序列，**没有投影层**；合并词表 58,592（图像 8,224 + 文本 50,368）。
- 两阶段训练（名字里 mix 的来源）：
  - S1 自回归预测下一个 token（703,671 步）
  - S2 掩码重建（50% 图像+文本 token 换 [MASK]，513,993 步）
- 数据：MIMIC-CXR + CheXpert + PadChest + BIMCV-COVID19 + Open-I，55 万训练对 / 6.27 亿 token。
- 结果：分类（高掩码率 40-80%）超 SigLIP/CheXagent 8.6%；图像补全超 VQ-GAN 51%；报告生成 GREEN 超 CheXagent 45%；**检索没赢**；**低掩码率 0-20% 打不过 SigLIP**（作者如实写了）。
- 算力：4×A100 80G，121 万步，总成本几万元 → **不可复现，只能读**。
- 与 MedViLL 对比（汇报核心）：两篇相隔五年主张一样（早期融合），但 MedViLL 靠掩码控制、CheXmix 干脆不要掩码（统一因果 + 任务靠生成什么来体现）。「掩码从核心创新退成不需要」。
- 诚实定位：**思路（图像 token 化 + 无投影层）借自 Chameleon，不是它原创；它原创的是两阶段训练 + 医学领域首次系统验证。**

### 🔴 飞书 PPT 图片坑（关键，别再踩）
- `<img src="@./相对路径/xxx.png" .../>` 这种 `@` 占位符**在 `slide create` 里能自动上传**，但**批量 create 时如果图路径写错会静默失败**（第一版 9 页全生成成功但一张图都没进去）
- 验证方法：生成后回读 XML 看是否有 `<img` 标签 + 检查 file_token
- 图片尺寸必须**严格按原图宽高比**算 `height = width / ratio`，不能按可用区域拉伸
